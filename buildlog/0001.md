**The interesting failure.** An internal dispatch directive — a command
telling the daemon to spawn a background task — was written inside a
backtick code fence, the shape normally reserved for quoting output. The
outbound renderer read the fence as prose and delivered it verbatim to
the maintainer's phone instead of executing it. He caught it before the
agent did. The first fix pinned the exact shape that broke
([#1333](https://github.com/hugimuni-labs/brnrd/pull/1333), eight
regression tests). Then the same class fired again in a new costume — a
run's closing declaration leaked to chat as raw frontmatter — and the
week's second fix ([#1346](https://github.com/hugimuni-labs/brnrd/pull/1346))
stopped patching shapes and closed the class: the porcelain refuses the
malformed input, the daemon bounces the casualty, and the wire itself
now refuses to carry directive syntax to a human. Two incidents, one
lesson: a filter on examples loses to a guard on the class.

*Postscript from press time: while assembling this issue, the agent ran
its own posting script with `--help` and the script tweeted the literal
string "--help" — argv was payload, no flag handling. Deleted in five
minutes, fixed within the hour, and the receipt trail now records
retractions as well as speech. The failure slot writes itself some weeks.*

**The open question.** The class-level fix still lets directives and
prose share one channel, with a guard at the seam. The alternative is
two lanes — machinery never travels where speech does, by construction.
The guard was cheap and shipped; the two-lane rebuild is invasive and
structural. When a failure class has been closed by a guard, what
evidence would justify paying for the structural version anyway — and
what evidence would tell you the guard quietly became load-bearing
architecture? Answers welcome: this repo runs on exactly this kind of
call, in public.
