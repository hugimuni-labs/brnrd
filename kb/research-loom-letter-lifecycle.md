## 1. The states

These are overlapping predicates, not an enum today: a letter can be accepted, shown, owed, unrunnable, and represented by a notice simultaneously. Handling is about obligation; channel delivery is a separate axis (`project.py:Fold:14`, `project.py:fold:47`, `router.py:Router.speak_out:351`).

| State/predicate | Facts or observations that put a letter there | Derivation/writer |
| --- | --- | --- |

| Port refused | Malformed file, failed append, or no live generation for letter/note/molt; file moved to `port/rejected` | `port.py:fact_from_port:379`, `loom.py:_reject:413`; a rejection notice goes only to a currently held room |

## 5. The table that could replace it

Proposed pure signature (not runtime code):

```python
letter_fates(ledger_union, main_snapshot) -> dict[letter_id, Fate]
Fate = (state, owes_next, next_act, reply_to, provenance, exposure)
# owes_next: ("thread", id) | ("loom", None) | ("person", id) | ("nobody", None)
# provenance: source id/event id, about/stands chain, sender thread, accepted lease gen
# exposure: current holder's shown ids + predecessor-shown lineage; never “work done”
```

A single state is **next-action state**, while `exposure` and `provenance` keep the orthogonal facts. Reply retires the inbound row; its outbound draft has its own row. Evaluate rows in the following declared priority. Main means a pinned tree plus closing-commit provenance, not whatever file is currently checked out. This table introduces observation/disposition facts named below; where today's ledger lacks one, it returns an observation debt rather than guessing (`project.py:Fold:14`, `loom.py:_reap:589`, `speak.py:speak:86`).

| Priority / state | Predicate from ledger and main | Who owes next | Next act | Existing source / missing fact |
| --- | --- | --- | --- | --- |
| 1 / fenced | Raw letter excluded by causal acceptance/lease fencing | nobody | None; retain raw history | T12; keep `project.py:fold`'s accepted-generation rules |
| 2 / channel-sent | Channel letter, all planned part receipts sent | nobody | None | T39/T40; needs send plan + all private part facts in input, or aggregate sent |

Rows 5–8 must preserve distinct reasons even though today's folded handled set loses them. Rows 3–6 delegate to a successor notice only while it remains unhandled; after its disposition the next owner is nobody. Attention-only outcomes need an explicit policy-named human owner, absent from today's bare attention facts. A bounced/climbed original can have a finished original obligation and a live successor obligation: output names the successor notice as `next_act`'s target, avoiding a second action on the original. Notice rows are independently projected and `stands` links disposition, not content equivalence (`project.py:fold:137`, `loom.py:notice:105`).
