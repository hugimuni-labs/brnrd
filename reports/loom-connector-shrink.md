## Candidates

| Candidate | Call and reason |
| --- | --- |
| Environment / direct interpreter | Retained. Direct Python argv would replace the shebang interpreter selection, but not the running-tree import path or the `BRNRD_HOME`/`STATE`/`CONFIG` contract. Home overrides may be non-Python executables. No interpreter-specific launcher was added merely to replace one PATH assignment. The GIT discovery scrub remains. |
| `_refuse` + failure counter | Taken. One quarantine branch handles malformed drops and exhausted ingest failures. Retry counters belong to `Inputs`, so restarting grants fresh tries. The terminal `.failures` diagnostic is written only on quarantine, preserving the existing oracle expectation. Attachment/diagnostic moves precede the letter move. |
| `channel_parts` / `carries` | Partly taken. `carries` remains the sole declaration parser and enabled-carrier lookup; the channel parser still checks address/chat syntax and calls it. The separate fake-address parsing branch is removed. Combining declaration syntax (`platform [edit]`) and address syntax (`channel:platform/chat`) would merge distinct validation jobs, not eliminate one. |
| Legacy speech fence | Taken. Removed the legacy raw-key / first-part send-store reads and only their parametrized test. The loom has no live ledger before cutover, so there is no live pre-folder intent to fence. Hashed-key intended/sent recovery, stale router checks, uncertainty and at-most-once behavior remain. Historical relay receipt migration is still a separate pre-cutover question. |
| Duplication in source/routing/port/project | Taken where concrete. Source and channel modules become sections of the connector module, deleting module overhead and an unnecessary `_letter` wrapper/recomputed id. Existing `port` parsing/clean validation, `project.fold`/`sender_threads`, and the atomic writer are reused. Routing address validation is retained: the standalone helper must still refuse malformed/bare fake addresses even if a reply thread is supplied. |

The remaining 25 interface lines were not removed in this pass. The report does not recategorize validation or omit blank/comment/import lines to claim compliance. Further work on the drop reader or supervision design is still needed to satisfy the 150-line ceiling.
